# 備份大小與雲端日期衝突修正驗證

日期：2026-10-11。基準 `e128b17473454b47e085335e6492caf133eece96`，隔離分支 `fix/backup-limit-cloud-date`。

## 修正

- V1／V2 匯出與下載共用同一個 JSON 序列化函式，檢查兩空格縮排、跳脫字元及 UTF-8 的實際大小。超過 5 MiB 時明確失敗，不建立下載 Blob、不裁切資料、不清除記事或草稿。V2 匯出也經同版本解析器檢查筆數、編號與刪除標記。
- 保留既有 5 MiB 匯入限制。解析前先用字串長度快速拒絕必定超限的內容，再檢查 UTF-8 位元組；檔案選取仍在讀取前檢查 File.size。序列化時逐一累計字串的 UTF-8 大小，遇到必定超限的資料提前中止，再對完整 JSON 做精確檢查，避免對所有大型正文建立完整 JSON。
- 接受雲端版本時先同步，再依記事 ID 從目前 store 取得日期，包含衝突顯示後再度移日的情況。已刪記事回原記事日期；沒有原記事的新建草稿則保留輸入日期。重新開啟且已取得雲端 ID 的新建草稿使用該 ID 查找。同步或草稿清除失敗時不導航、不顯示成功。

## 實際結果

- Node：原有 39 項加新增 24 項，共 63 項全數通過。覆蓋 V1／V2 在 5 MiB − 1、正好 5 MiB、5 MiB + 1 的 ASCII／中文／emoji 邊界、縮排大小與 JS 字串長度差異、正常解析及真正匯入測試 cloud store 後再匯出、非法快照、拒絕匯入不讀取／不同步／不變更資料。
- 編輯器回歸直接執行正式事件處理函式與真實 createCloudStore，RPC 與持久層只用測試資料。涵蓋儲存／刪除衝突、再度移日、日期未變、已刪記事、取消、同步失敗、草稿清除失敗與重新開啟的新建草稿。
- 將同一組新增回歸測試套用到原始程式，22 項中 13 項失敗；還原修正後完整 63 項通過。證明測試會抓到原錯誤。
- `npm run check`、四個修改模組的 `node --check`、`npm run build:vendor` 成功。使用原 checkout 的已安裝依賴副本，`npm ls --depth=0` 確認 Supabase 2.108.1 與 esbuild 0.28.2，符合鎖定版本。建置只有換行差異，已恢復 vendor，未改 SDK。
- 隔離無頭 Chrome：8 項通過。使用 index.html 的真實 DOM、正式 editor／cloud data panel、File／DataTransfer 與 Blob，驗證移日／同日／已刪衝突、下載 Blob 可解析、有效／超限／損壞選檔、超限匯出沒有 Blob。測試頁沒有載入 app 啟動、認證或正式設定，只使用記憶體資料與模擬 RPC。下載連結在測試頁攔截，未寫入使用者下載目錄。
- 瀏覽器測試頁未捕捉到頁面 error 或 unhandledrejection。Chrome stderr 出現本機擴充功能 registry 缺值訊息，非頁面錯誤。內建電腦操作工具初始化失敗，後以獨立 Chrome 子程序完成驗證。

重現 Node：`npm test`。重現瀏覽器：以 HTTP 靜態伺服器提供此 repo，開啟 `/scripts/browser-regression.html`；應顯示 `PASS 8 browser checks`。測試頁使用自行產生的資料，沒有正式 Supabase 寫入。

## 限制

此修正拒絕超限匯出，沒有加入分片備份、壓縮或提高匯入容量。超過 5 MiB 的完整資料與既有超限備份仍不能經此匯入流程還原；原資料仍保留。雲端記事／草稿／刪除標記的既有筆數上限不變。未執行正式 OAuth／Supabase、兩台實體裝置或手機驗收。
