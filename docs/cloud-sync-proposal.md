# 同帳號跨電腦同步提案

狀態：2026-10-10 說明提案，尚未加入網站。現有 localStorage 不會因為登入同一個 Chrome、Google 或 GitHub 帳號而同步。立即換電腦可匯出 JSON、搬移備份，再在另一台電腦手動還原；之後的修改仍需再次搬移。

建議下一階段使用 Supabase Auth + 私人 Postgres 資料表，登入可選 Google 帳號或電子郵件驗證碼。理由：GitHub Pages 提供靜態網站，無法自行提供私人帳號記事資料庫；Supabase 提供登入、資料庫及逐筆權限（RLS），可由現有前端連接，不必為個人網站另架伺服器。

操作目標：電腦 A 登入 → 匯入既有本機記事（先備份、預覽、確認）→ 儲存並同步 → 電腦 B 登入同一個網站帳號 → 看到相同記事。網站仍可公開瀏覽，記事只允許本人讀寫。正式記事上傳雲端，草稿先保留各裝置本機，避免兩台電腦互相覆蓋尚未完成的輸入。

實作前需決定及驗證：

- 登入方式、使用者持有的 Supabase 專案、服務用量與費用。
- 每筆記事綁定 owner ID，RLS 驗證讀取／新增／修改／刪除；匿名與另一個帳號不得讀寫。
- 保留本機輸入，區分「已存本機／待同步／已同步／同步失敗」。第一版可要求網路可用才完成雲端保存，勿把本機暫存誤報雲端成功。
- 兩裝置同時修改需檢查資料版本並提供衝突處理，不直接以最後寫入覆蓋。刪除需同步刪除標記，防止另一台舊資料再次把記事復活。
- 本機資料移入雲端前由使用者選擇，切換／登出帳號隔離快取；備份／還原與資料匯出仍保留。
- 前端只能使用公開 publishable key，service role／secret key 不放入 GitHub Pages 或 repository。

成本與取捨：增加雲端服務、登入與網路依賴，記事會由選定的雲端供應商保存。現階段無需加入第三方服務；先完成本次驗收，再討論與授權同步版本。

官方文件：[Auth](https://supabase.com/docs/guides/auth)、[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。
