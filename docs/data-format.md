# 保存與備份格式 V1

目前全部資料放在一個專案專用 localStorage 項目 `cat-days:data:v1`，包含 app、version、revision、notes、drafts、noticeShown。每次操作先讀取及驗證，產生完整新資料，再用一次 setItem 寫入；成功前不顯示成功或清空表單。讀取失敗／損壞不當作空白資料覆蓋，可到「資料與備份」下載原始內容。

瀏覽器提供 Web Locks 時，寫入會以同來源的專案鎖排序。編輯與草稿另外核對完整舊記錄，拒絕舊分頁覆寫。沒有 Web Locks 的瀏覽器仍會核對舊記錄，但不保證極短瞬間跨分頁同時寫入的序列化；建議單一分頁編輯。網站沒有網路上傳記事的程式。

JSON 備份的頂層欄位為 `app: "cat-days"`、`version: 1`、`exportedAt`、`notes`、`drafts`；不包含本機 revision 與首次提醒設定。UTF-8，最多 5 MiB，每種記錄最多 5,000 筆；記事文字與心情文字各最多 20,000 個 JavaScript 字元。筆數與檔案大小採上限，是避免錯誤檔案耗盡裝置資源，並非保證 localStorage 容量；實際容量以瀏覽器為準。

記事欄位：id（1～128 字元）、date（有效 YYYY-MM-DD，1900～2100）、text、mood、moodText、createdAt、updatedAt；時間為 UTC ISO 毫秒格式。mood 可空白或 🙂／😌／😐／😔／😣。文字／表情／心情文字至少一項。衝突副本保留 originId，介面標示「匯入副本」；編輯不改 createdAt。裝置時間倒退時，updatedAt 至少比舊值增加 1 毫秒。

草稿另有 id、slot（new／edit／recovery）、noteId（沒有則 null），以及 date、text、mood、moodText、updatedAt。新記事草稿 id 固定 new；既有記事編輯草稿為 edit:記事編號。草稿可保留未選日期及空白內容，正式儲存時才檢查內容必填。匯入草稿為 recovery，可從「資料與備份」恢復為新記事；不覆蓋目前新記事或編輯草稿。

匯入先驗證全部記錄、重複編號、日期及編輯草稿關聯，再顯示預覽。相同編號／來源且使用者內容一致時略過（時間戳變化不算內容變化）；同 ID 不同內容保留新 ID 副本。預覽後資料有變動則要求重新預覽。重複匯入仍存在的同份內容不增加副本；已刪除或已轉為正式記事的草稿，可能因舊備份再次恢復，這是備份的恢復行為。

資料版本改動需新增明確遷移程序；目前拒絕其他版本。輸入與匯入內容均以純文字顯示。沒有加密、帳號或自動同步；使用相同瀏覽器設定檔與來源才能讀到原資料。關閉前仍在處理的草稿，或儲存失敗的輸入會觸發瀏覽器離開提醒，但行動系統強制終止時不保證提醒顯示，應確認「草稿已暫存」或手動儲存。
