# 兩台電腦同步驗收

2026-10-11 使用者回覆「兩台電腦均通過」，確認同帳號的新增、修改、刪除同步，以及重新整理後再登入取回雲端資料。兩台實體電腦的基本同步驗收完成。下列衝突、保留兩份、刪除衝突及裝置草稿項目尚未收到實機回報，保留作為延伸檢查清單。部署與登入驗證結果見 cloud-validation.md。

網站：https://linhercherng.github.io/cat-days/#sync

## 開始前

1. 電腦 A、B 使用同一網址及資料庫允許的同一 Google 帳號。
2. 各自開啟「帳號與同步」並登入，畫面應顯示正確帳號及「已同步」。重新整理後需再次登入，這是記憶體登入的既定取捨。
3. 原本機記事不會自動上傳。若要搬移，在原裝置依序下載舊本機備份、確認下載成功、預覽及確認匯入。不要清除瀏覽器資料；其他裝置不需重複匯入同一份資料。
4. 新建測試記事 `同步驗收 A`，只對測試記事操作。正常記事及心情文字不需提供給製作者。

## 依序操作

| 檢查 | 操作 | 通過條件 |
|---|---|---|
| 新增 | A 在今天新增 `同步驗收 A`，按「儲存記事」；B 按「立即同步」後看今天 | B 顯示同一筆記事，A 有雲端儲存成功提示 |
| 修改 | B 修改為 `同步驗收 B 已修改` 並儲存；A 立即同步 | A 顯示最新文字，沒有多出一筆副本 |
| 刪除 | A 刪除這筆測試記事；B 立即同步 | B 的單日與本週列表都不再顯示 |
| 重新登入 | A 新建另一筆 `同步驗收 重開` 並儲存；B 重新整理、再次登入 | B 能取得雲端記事，不依賴 B 的本機原記事 |
| 編輯衝突 | 新建測試記事，A/B 都開啟同一筆編輯。A 先改成 `A 的版本` 並保存，B 改成 `B 的版本` 再保存 | B 提示衝突，B 的输入仍在，雲端 A 的版本未被覆蓋 |
| 保留兩份 | B 在衝突畫面選「保留兩份／另存新記事」；兩台同步 | A/B 各有一筆，兩台看到一致內容 |
| 刪除衝突 | A/B 開啟同一測試記事，A 刪除，B 用原編輯畫面嘗試保存 | B 提示已刪除，不能復活原記事；若選另存，只建立新記事 |
| 裝置草稿 | A 輸入新記事但不保存，離開編輯畫面後重新整理及登入；B 同步 | A 可繼續草稿，B 不會出現 A 尚未保存的內容 |

頁面回到前景、每分鐘及保存後會查詢變更；驗收時使用「立即同步」可避免等待。正在編輯的文字不會被背景同步替換；保存時才檢查衝突。

## 若有問題

請回報哪一項、哪台電腦、瀏覽器名稱及畫面錯誤文字即可。不要提供 Secret、登入網址中的驗證碼、token 或私人日記內容。

測試結束後可在網站刪除這些測試記事並同步。每台電腦的草稿各自處理；正式記事刪除會傳到另一台。

驗收紀錄分開列出：程式／隔離資料庫測試、真實 Google 與 Supabase 登入讀寫、使用者兩台實體電腦。此次確認的四項基本同步操作已通過；其餘項目不因基本同步通過而自動標示完成。
