# 跨裝置同步定稿

2026-10-11：使用者確認四項建議，授權開始製作。原 V1 日期、節日、手機畫面與文字上限延續。

## 使用方式與資料歸屬

- 網站與 repository 公開；記事不進 GitHub。未登入維持原本的本機模式。
- Supabase Auth + Google 登入，只允許一個指定、已驗證的 Google 帳號存取雲端資料。允許名單在資料庫私有區域設定，不能只靠前端隱藏。
- Google 僅授權基本身分；記事存在 Supabase Postgres。資料表啟用 RLS，匿名與其他帳號不能讀寫。
- 雲端正式記事和舊本機記事分開。登出隱藏雲端記事；切換帳號不能讀到前帳號草稿。
- GitHub Pages 保持靜態部署。2026-10-11 使用者確認採用登入憑證只存在記憶體；PKCE 驗證碼暫存在 sessionStorage，完成登入即移除。重新整理／重開需再次 Google 登入，雲端記事與本機草稿仍保留。

## 草稿、保存與同步

- 草稿只在目前裝置，依帳號隔離，不上傳；輸入後立即暫存。斷線仍可寫草稿。
- 正式新增、修改、刪除需網路與有效登入。失敗保留草稿；網路恢復後由使用者重新按儲存，不自動排隊上傳。
- 雲端回覆成功才顯示已儲存。回覆遺失可重試相同操作編號，不產生重複記事。
- 登入、視窗回到前景、保存後、前景每 60 秒及「立即同步」檢查變動。背景同步不重新填入編輯欄位。
- 使用伺服器版本做原子比較；時間只供顯示，不決定誰的修改勝出。雲端讀取分頁並包含刪除標記。
- 每筆正文、心情補充各最多 20,000 UTF-16 單位；每帳號最多 5,000 筆有效記事。日期仍為 1900～2100 年。

## 衝突與刪除

- 同一篇在兩裝置修改：提示雲端與目前輸入。可「保留兩份」另存目前內容，或「使用雲端版本」明確捨棄目前草稿；沒有覆蓋雲端選項。
- 未決定前保留草稿。重開編輯草稿也必須帶原始版本，不能把舊草稿當作最新版。
- 刪除先確認；伺服器成功後清除正文、日期及心情，保留 ID、版本與刪除時間，供其他裝置同步。
- 已刪記事不能被舊版本更新、匯入或遺失回覆的重試復活。編輯已刪記事可明確另存新記事。

## 舊資料匯入與備份

- 登入不自動上傳。顯示目前帳號 → 先下載舊本機備份 → 預覽新增／相同略過／衝突副本／已刪略過 → 明確確認匯入。
- 相同 ID、相同內容略過；同 ID 不同內容保留雲端並新增副本。不同 ID 的相同文字仍是不同記事。
- 已刪 ID 預設略過；另外提供明確的「恢復為新記事」選擇。
- 匯入逐筆確認，顯示成功與尚未完成數量；重試不重複建立，期間雲端變動會重新檢查。
- 原本機記事不自動移除，原草稿不自動搬入帳號。備份 V1 可匯入；雲端 V2 備份含有效記事、刪除標記與這台裝置草稿，不含登入憑證。
- 舊備份的刪除標記在雲端沒有此 ID 時補入，避免空白帳號還原後再被舊 V1 備份復活；不刪除目前仍有效的雲端記事。下載檔沒有加密。

## 費用與營運

先用 Supabase Free。官方目前提供 500 MB 資料庫、50,000 每月活躍使用者及 5 GB 傳出流量；低活動專案可能一週後暫停，免費方案無自動資料庫備份。定期手動備份，暫停時先恢復服務，失敗不能顯示同步成功。不自動升級付費。Pro 起價 USD 25／月，額外專案與超額用量需另評估。

來源：[價格](https://supabase.com/pricing)、[Google 登入](https://supabase.com/docs/guides/auth/social-login/auth-google)、[PKCE](https://supabase.com/docs/guides/auth/sessions/pkce-flow)、[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。

## 製作順序

1. 定稿規格、資料契約與驗收情境。
2. 資料庫 migration：私人允許名單、RLS、版本比較、冪等操作及刪除標記；在隔離 Postgres 測試。
3. 雲端資料層：分頁同步、帳號隔離草稿、離線與不確定回覆重試。
4. Google PKCE 登入、登入狀態、登出與手動同步入口。
5. 接入既有首頁／月曆／單日／編輯；衝突、已刪另存與草稿恢復。
6. 本機匯入、V1/V2 備份、預覽與可重試還原。
7. 自動化資料測試、真實瀏覽器本機回歸、手機布局與錯誤提示。
8. 使用者持有的 Supabase 專案及 Google OAuth 設定、指定帳號允許名單；不得公開 client secret／service role。
9. 真實登入、RLS、兩瀏覽器併發與失敗測試後，啟用 GitHub Pages 雲端設定。
10. 使用者兩台電腦驗收，確認後才宣告跨裝置同步完成。

## 驗收方式

| 情境 | 通過條件 |
|---|---|
| 既有網站回歸 | 未設定／未登入仍可使用原本 CRUD、草稿、備份、日期及節日功能 |
| 登入權限 | 指定 Google 帳號成功；匿名及另一帳號直接 API 存取均失敗 |
| 兩裝置 | A 新增／修改，B 同步可見；清除 B 本機正式記事快取也能再讀取 |
| 匯入 | 不自動上傳；備份與帳號明確；同檔重試不重複；中途中斷可續傳 |
| 衝突 | A/B 各自修改同版本，第二個保存被阻止；兩份或採用雲端均無悄悄覆蓋 |
| 草稿 | 離線／重開／衝突後內容保留；背景同步不改输入；不同帳號互相隔離 |
| 刪除 | A 刪除後 B 消失；舊編輯、重試與備份不能復活原 ID；伺服器正文已清除 |
| 網路錯誤 | 提示未保存／同步失敗；遺失回覆重試不重複；登入失效不丟輸入 |
| 備份還原 | V1 相容；V2 保留標記及草稿；損壞檔阻止；備份不含 token |
| 登出 | 雲端記事隱藏，憑證清除；本機原記事保留；草稿有明确提醒 |
| 正式環境 | OAuth callback 正確、部署版本可核對；實際兩台電腦驗收 |

驗收紀錄必須區分「本機／模擬測試」「隔離資料庫測試」「真實 Supabase 與 Google」「使用者兩台電腦」；前兩項不能替代後兩項。
